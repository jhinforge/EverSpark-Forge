# 分布式部署恢复与进度

## 恢复规则

- Node Agent 由 `Legate.Envoy.supervisor` 监督。异常退出后重新启动；显式停止 supervisor 后保持停止。
- Agent 的独立心跳线程在长时间安装期间继续续约。主机以自身的单调时钟判定租约过期，离线节点不提供可用资源。
- 节点身份、Agent 运行身份和连接标识分别表示机器、进程生命周期和连接变化。租约过期后恢复心跳会更新连接标识，即使 WebUI 没有观察到离线状态，也会触发 Forge 重连验证。
- Concept 和 Image 的重连检查复用 `ConnectionVerification`，只检查健康与源码版本。失败后保留手动验证入口，避免每次轮询自动重试。
- Agent 在执行前记录任务意图，完成后记录结果。重启后已完成任务重放结果；执行中断的任务返回“结果未知”，不自动重复命令。
- 主机在 Image 部署期间重启后，使用已保存的任务 ID 查询 Agent 日志。确认完成后检查健康与版本；确认失败后显示失败阶段和退出码；无法确认时保留“结果未知”。旧任务记录缺少恢复元数据时，也按结果未知处理。
- 恢复和验证期间不能启动同一个 Forge 的另一项部署任务。节点在线仅表示 Agent 可以通信，Forge 可用还需要健康检查。

## WebUI 部署展示

部署继续使用原有安装脚本；脚本输出阶段标记，Agent 经认证心跳报告给主机。WebUI 显示初始化、系统依赖、Ollama/ComfyUI 下载、Python 环境、PyTorch、Image 依赖、模型下载工具、模型下载、模型导入、服务启动和健康检查。

每个阶段显示实际耗时。模型下载显示已在本地就绪的模型数，例如 `0/1`、`1/1`；这不是单个模型的字节百分比。缓存中已有的非空模型计入就绪数量。其他下载工具没有统一的字节进度接口，因此显示实际阶段和耗时，不估算百分比。

心跳失联时显示“心跳中断，等待恢复”，保留最后一次进度。部署失败和执行超时保留阶段、退出码及有长度上限的末尾诊断；恢复查询也保留 Agent 记录的失败阶段。

## 验证

自动测试覆盖真实 Agent 进程重启、部署子进程随 Agent 消失而停止、任务结果重放、Image 主机重启恢复、轮询间断线、验证期间断线、失败验证不误报就绪、超时诊断和模型计数。

真实 Pod 验收：分别在依赖安装和模型下载时观察 WebUI；中断再恢复节点网络；结束 Agent 进程并观察监督重启；在 Image 部署时重启主机。检查恢复过程不重复安装、就绪状态经过健康验证、失败可定位到具体阶段。自动测试不能替代真实 GPU、供应商网络和安装依赖的验收。

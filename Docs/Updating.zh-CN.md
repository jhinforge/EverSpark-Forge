# 更新指南

主机、客户端和节点是不同运行位置，更新其中一个不代表其他位置已更新。首次使用见[Getting Started](Getting-Started.zh-CN.md)。

## 更新前

等部署、生成、模型传输和下载完成，再关闭主机；导出角色与 Memory、保存 Pod 输出和私人配置。记录“关于”页的版本／提交。更新前后的节点连接和账户需要复查，不要把代码备份当作用户数据备份。

## Windows ZIP 客户端

1. 从官方发布入口获取新 standard 或 full 包，按公布校验值核对。
2. 关闭旧客户端，将新版完整解压到新目录，保留旧目录用于回退；不要只替换 EXE 或只替换 Python。
3. 同一电脑需要沿用数据时，在关闭状态下复制原 `.env` 和需要的 `Data/`，或使用数据 ZIP 恢复角色与 Memory。私人配置需另行迁移，不覆盖新版 `Runtime/` 或源码。可选浏览器配置也在 Data，失败时不要强行沿用。
4. 启动新版，检查“关于”、账户、Node 绑定、云端配置和生成链路。

当前 Windows 用户的 Vast 凭据和默认 `%LOCALAPPDATA%/EverSpark/` 状态不在 ZIP 内；换电脑需重新配置。Tailscale auth key 只在当前会话内，租新 Pod 前重新提交。详见[数据指南](Runtime-and-Data.zh-CN.md)。

## Windows 源码主机

关闭运行中的主机，在仓库根目录执行：

```powershell
git status
# 工作区干净，或已另行保存自己的修改后：
git pull --ff-only origin refactor/distributed-architecture
.\everspark.cmd archon start
```

`--ff-only` 失败时先处理自己的提交或分支分歧，不使用强制重置覆盖修改。此命令针对当前开发分支；正式版本发布后以发布说明中的分支或标签为准。

## 已有 Pod

主机更新不自动升级既有 Pod 的代码和正在运行的进程。按机器卡片的部署／重新部署流程更新对应 Forge；验证源码与服务健康后再选用。

Agent、模型存储服务、媒体 URL 服务是不同进程。只重启 Agent 不保证已加载旧代码的独立模型存储服务刷新。更新节点源码后，还需重启受影响的模型存储／媒体服务；维护过程中可在保存输出并确认无任务后重启 Pod，再验证 Forge。更换 Audio 依赖时使用 Audio 重新部署流程，不在其他 Forge 环境里混装依赖。

重启或服务退出可能丢失内存任务状态；无法确认的任务不要自动重复提交。源码版本不一致、结果未知的处理见[排障指南](Troubleshooting.zh-CN.md)。

## Linux 单机模式

停止托管服务、保存私人数据、更新源码，再按版本要求运行 setup 与启动。`setup --plan` 可先查看准备安装的内容；重复安装运行时不等于恢复数据。

## 更新后复查

检查启动、已有 Node 重连、对应 Forge 健康、一次生成及下载。新旧版本回退时也需恢复兼容的数据备份；不要让两个主机同时写同一数据库。
